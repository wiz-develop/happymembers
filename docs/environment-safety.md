# 環境別ソースの取り扱い

## ブランチと配置先

| 環境 | Gitブランチ | WordPressテーマ |
| --- | --- | --- |
| 本番 | `main` | `/htdocs/ikou_www/happymembers/cms/wp-content/themes/happy-members` |
| テスト | `test` | `/html/cms/wp-content/themes/happy-members` |

企業サイトの `/htdocs/ikou_www/wordpress/wp-content/themes/happyfamily` は、このリポジトリの管理・反映対象外です。

## 必須ルール

- `main` と `test` はテーマ全体を同期しない。ブランチのマージ結果をそのままFTPへ全量アップロードしない。
- 反映前にFTP上の対象ファイルを退避し、対象ファイル単位で差分を確認する。
- `assets/api/v1/common/config.php` はGit管理しない。FTP上の環境別ファイルを維持する。
- API接続先、認証キー、メール送信先、デバッグ処理などの環境固有値を別環境の値で上書きしない。
- テスト環境だけに存在するファイル、本番環境だけに存在するファイルを一括同期で追加・削除しない。
- 本番反映は `test` ブランチの全体マージではなく、確認済みの修正コミットまたは対象差分だけを `main` へ移植する。

## 今回の空注文対策で反映するファイル

テスト環境へ反映する対象は次の3ファイルだけとする。

- `functions.php`
- `page-cart__confirmation.php`
- `assets/js/order.js`

`functions.php` と `page-cart__confirmation.php` にはテスト環境固有のメール送信先・確認用処理があるため、テストFTPから取得した内容を基準に空注文対策だけを追加している。本番用ファイルで上書きしない。

## E2E実行時の注意

- E2Eはテスト環境以外では起動しないようホスト名を検証する。
- 専用テスト会員を使用し、開始前のカートが空であることを確認する。
- テストは有効な注文を1件作成し、その直後の別画面からの再送が空注文として拒否されることを確認する。
- 注文確認メールが送信されるため、実行前に関係者へ影響を確認する。
- 認証情報は `e2e/.env` または環境変数で渡し、Gitへコミットしない。
- テスト結果のスクリーンショット・動画・トレースは、会員情報を残さないため保存しない。

## 2026-09-15 検証記録

テスト環境 `http://happyfamily-members.3d-showcase.net` に今回の3ファイルだけを反映し、Android Pixel 7相当のE2Eを実行した。

- 有効なテスト注文：1件だけ受付（HTTP 200 / `code=0`）
- 別の注文確認画面から、受付後の空カートを送信：拒否（HTTP 409 / `code=2`）
- 受付済みの同一注文トークンを再送：拒否（HTTP 409 / `code=3`）
- 未ログイン状態から注文APIを実行：拒否（HTTP 401 / `code=4`）
- 実行後のテスト会員カート：0件

E2Eは1件成功し、空注文および重複注文は作成されなかった。認証情報とブラウザのテスト成果物はGitへ保存していない。
